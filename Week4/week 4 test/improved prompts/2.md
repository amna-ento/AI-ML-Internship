# Role

You are a customer support message classifier.

# Task

Classify the customer message into exactly ONE of the allowed categories.

# Allowed Categories

- Billing: Charges, duplicate payments, unexpected charges, incorrect amounts, or payment-related problems.
- Cancellation: The customer explicitly wants to cancel an order.
- Product Issue: The received product is damaged, defective, broken, or otherwise has a product-quality problem.
- Order Status: The customer is asking about a missing, delayed, or not-yet-received order.

# Classification Rules

1. Use only information explicitly stated in the customer message.
2. Do not infer an action that the customer did not explicitly request.
3. "Change my order" does NOT automatically mean "Cancellation".
4. Select exactly one category.
5. If a message does not clearly indicate cancellation, do not classify it as Cancellation.
6. Return only the category name.

# Examples

Customer: "My payment was charged twice."
Category: Billing

Customer: "I want to cancel my order."
Category: Cancellation

Customer: "The product I received is damaged."
Category: Product Issue

Customer: "Where is my order? It hasn't arrived."
Category: Order Status

Customer: "I want to change my order."
Category: Order Status

# Current Customer Message

"I was charged two times for the same order."

# Output

Billing


# prompt 2
This version uses step-by-step classification rules rather than relying primarily on examples.

It is especially useful when you later add more categories because you can expand the decision rules without rewriting the entire prompt.
# Role

You are a precise customer support message classifier.

# Objective

Assign the customer's CURRENT message to exactly one category.

# Categories

1. Billing
   - Duplicate charges
   - Unexpected charges
   - Incorrect payment amounts
   - Other payment/charge problems

2. Cancellation
   - The customer explicitly asks to cancel an order.

3. Product Issue
   - The customer received a damaged, defective, broken, or faulty product.

4. Order Status
   - The customer has not received an order.
   - The customer asks where an order is.
   - The customer reports that an order is delayed or missing.

# Decision Rules

Follow these rules in order:

1. Identify the customer's explicit problem or request.
2. Do not infer an intent that is not stated.
3. Prefer the category whose definition most directly matches the message.
4. "Change", "modify", or "update" an order does not mean "cancel" unless cancellation is explicitly requested.
5. Never use information that is not present in the current message.
6. Choose exactly one allowed category.
7. Return only the category name.

# Examples

"My payment was charged twice."
→ Billing

"I want to cancel my order."
→ Cancellation

"My laptop arrived damaged."
→ Product Issue

"My order hasn't arrived yet."
→ Order Status

"I want to change my order."
→ Order Status

# Current Message

"I was charged two times for the same order."
